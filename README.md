## 📖 项目简介

**Alongside · 在你身边 — AI 人生协助系统**  
*赛道：人工智能+*

### 【背景】
随着 AI Agent 生态逐步走向繁荣与分化，用户面对的是日益碎片化的工具与模型。人们越来越需要一个归属于自己、不被单一厂商绑定的底层系统，去连接、整合不同的 Agent、现实工具与个人生活资料。

### 【愿景】
让普通人不必先学会配环境、调插件、研究各类复杂的 Agent 架构，就能一键拥有一套真正帮得上忙的 AI 人生协助系统，享受到 AI 时代的红利。  
我们希望 AI 能够分担生活中的杂乱、繁琐与重压，放大个人的思绪与行动，让每个人更有从容和余力，去探索属于自己的方向、意义与生活体验。

### 【工作形式】
外部的任何 AI 可以在用户部署的系统平台里面注册各自身份，获得对应权限，与用户一起使用系统平台，借助系统的插件，实现各种功能，以及外连各种软件、网页、成熟的生态等等。

### 【特点】
1. **架构灵活，一切皆插件**：这套系统架构灵活（无特权内核+一切皆插件），功能可以借助插件无限扩展，可以从外部接入市面上任何 AI Agent，可以借助插件整合包一键装配启动，并且可以随时调整、自由搭配。
2. **能力治理，安全可控**：项目本身把『Agent 协助』当成一等工程问题，为它建立形式化基础，通过能力声明、权限分级与回滚审计，让 AI 能深入协助生活，又把安全与控制权牢牢留在人手里。
3. **全面开源，自由共创**：项目本身全面开源，欢迎共创者、插件开发者、整合包开发者等，并支持本地全面自定义、个性化调整。

### 【项目现状】
项目已完成早期的个人概念验证原型（PoC），验证了核心逻辑的可行性；随着团队组建完成，目前已完成全局定调与初步分工，正在向规范化、工程化的系统重构迈进。

### 【项目发展方向】
分阶段前进：
1. **切入与闭环**：首先，把第一个官方整合包做好——聚焦『生活事务整理』（涵盖日常账单、待办、日程与自动周报；相比传统分散的效率工具，重点突破跨数据源整合的流畅度与主动式、可审计的人机协作体验），通过“需求→功能→用户→反馈→迭代”的正向飞轮，去持续生长 插件、功能与整合包 体系。  
   *（每个需求形成一个插件圈，即一组插件组成的功能体系，既解决用户问题，又把需求背后的用户转化为目标用户，用户的反馈又会提供新的需求落点与新的优化点，我们的项目借此持续发展。）*
2. **验证价值**：其次，在项目被使用的过程中，项目会通过人与 AI 的协作体现差异，再逐步验证插件整合包的易用性、可控性与生态扩展价值。
3. **传播与生态**：然后，靠分发、自媒体、整合包生态、比赛亮相等等，让项目被人看见，逐步吸纳用户、迎接共创者、迭代项目……让项目越变越好、普及开来。
4. **时代探问**：最后，我们希望借此尝试探明一个问题：  
   *“在 AI 已经开始普及，但人与 AI 协作关系尚没成型的时代中，AI 这块新时代的地基，会催生怎样的成长？”*  
   希望可以给出我们的回答（暂时的，并不确定）：  
   *“以 AI 为新地基，协助每一个人在繁杂的世界中更清晰、更从容地生活与成长。”*

## 🎯 设计取向

- **一切皆插件**：插件在 `manifest.json` 里声明自己的窗口、路由、权限与能力，内核机械地发现它们。
- **MCP 是 AI 的正门**：插件声明的能力会映射成 MCP 工具，外部 Agent 可以像调用本地能力一样调用它们。
- **数据主权**：所有数据在一个 `data/` 目录里（SQLite + WAL），迁移 = 复制目录，备份 = 复制文件。

### 命题要高，锚点要实，证据要散

这个项目想回答的不是「怎么管理时间」，而是「**AI 和人到底是什么关系**」。所以三件事得同时成立：

| 维度 | 要求 | 具体落实 |
|:--|:--|:--|
| **命题要高** | 别把问题问小了 | 问的是 AI 和人的关系，不是某个单一功能好不好用 |
| **锚点要实** | 落在一个真实的人身上 | 先让几个人真实地用一段时间，看它对人有什么实际影响 |
| **证据要散** | 别指望一句空洞结论 | 靠一件件看得见的生活变化，而不是一句高深的空话 |

**让高处的命题，从低处的人的体验里自然长出来。**  
> 如果把宏大理念拆得太细、太简单，反而会失掉它作为「问题内核」的重量。把「AI 和人的关系」改成「一个帮你整理日程的软件」，可这是**降维**，而不是落地。  
> 人和 AI 的关系当然很好说，但**人和 AI 的关系，必须通过一个人的真实变化来证明。**

## ⚡ 5 分钟上手

### 前置依赖

| 依赖项 | 版本要求 | 说明 |
|:--|:--|:--|
| **Node** | 20+（见 `.nvmrc`） | 前端构建与开发服务器 |
| **Python** | **3.11.x**（锁定，别用 3.12/3.13） | 后端运行时 |
| `make` | 可选 | **没有也能用**，跨平台脚本完全兼容 |
| `docker` | 可选 | 只在服务器部署时需要，本机开发不需要 |

> **没有 `make` 也能用。** 项目入口的真实实现是跨平台脚本 `tools/task.py`，根目录 `Makefile` 只是它的薄壳。两条路**行为完全一致**：
> ```bash
> make dev                     # 有 make 的机器
> python tools/task.py dev     # 任何机器都能跑（推荐，含 Windows 无 make 的情况）
> ```

### 三条命令跑起来

```bash
python tools/task.py setup    # 1. 首次：建 venv + 装前后端依赖（初次会稍慢）
python tools/task.py dev      # 2. 同时启动前端与后端开发服务
python tools/task.py verify   # 3. 交付前自检：lint + test + 构建
```

服务就绪后访问：
* 前端工作台：http://localhost:5173 （开发服务器，热更新）
* 后端 API 文档：http://localhost:8000/docs （FastAPI 自动生成）
* 健康检查接口：http://localhost:8000/healthz （返回 `{"ok":true}`）

*(终端按下 `Ctrl+C` 会平滑停止前后端全部服务。)*

### 常用命令速查

| 命令 | 作用说明 |
|:--|:--|
| `setup` | 初始化虚拟环境并安装全部依赖（首次运行） |
| `dev` | 一键同时拉起前端 5173 与后端 8000 服务 |
| `lint` | 前端 tsc + eslint + prettier ／ 后端 ruff + mypy |
| `test` | 前端 vitest ／ 后端 pytest 自动化测试 |
| `verify` | **交付与提交前必跑**：lint + test + 前端构建全量校验 |
| `build` | 编译前端静态产物（有 docker 环境时顺带构建镜像） |
| `clean` | 清理临时构建缓存，**`data/` 个人数据目录绝不会被触碰** |
| `new-plugin --id x --name "名字"` | 一键生成标准化插件模板骨架 |

## 🚀 服务器端部署

Alongside 本体非常轻量（FastAPI + 静态 Web 资源）。但若需要在云端完整运行「理财」与「智能体」插件，需配置以下配套环境：

| 附属服务 | 对应功能模块 | 建议安装方式 | 关键说明 |
|:--|:--|:--|:--|
| **Node ≥ 22.19** | 「智能体」插件运行环境 | [官方安装包](https://nodejs.org/) 或 nvm | 前端构建仅需 Node 20+，但 pi 依赖严格要求 ≥22.19，推荐直接装 22.19+ |
| **pi CLI** | 智能体命令行引擎 | `npm i -g --prefix ~/.npm-global` | 插件默认在 `~/.npm-global/bin/pi` 寻址 |
| **pi-web-ui** | 智能体 Web 交互座舱 | `npm i -g pi-web-ui` | 独立后台服务（默认 8787），配合 Nginx 反代与鉴权 |
| **BeeCount-Cloud** | 财务与记账支持 | `docker pull sunxiao0721/beecount-cloud` | 独立私有账本服务，插件经 MCP 只读对接 |
| **Nginx + SSL 证书** | 公网安全访问入口 | acme.sh / Certbot | 启用 HTTPS，硬性要求配置 `/api/` 路由不缓存 |

> **提示：以上附属服务非强制要求。**  
> 插件均支持单独开启或禁用。若仅需日常的日程、待办、习惯与个人笔记，直接运行本体即可完整使用。  
> 完整部署脚本位于 [`deploy/`](deploy/) 目录，逐步指导参见 [`deploy/README.md`](deploy/README.md)。

## 🛡️ 设计边界（给使用者）

Alongside 坚持**单人、自托管**的个人系统原则，以下设计是有意为之的选择：

- **不做多租户与公网社交**：没有公开注册、没有群组广场、不收集用户数据 —— 你的系统只服务于你与你授权的 Agent；
- **纯粹的数据主权**：所有数据均在本地 `data/` 目录中，换机器只需打包目录，离开时可以带走全部数字足迹；
- **内核杜绝业务硬编码**：`kernel/` 与 `core/` 中绝不出现 calendar/todo/finance 等特定业务词汇，确保底层永不膨胀。

## 🤝 协作规则（人与 AI 共同遵守）

本项目的开发由**人类与 AI Agent 共同推进**。为了保证工程质量，我们制定了清晰的协作约定：

### 通用工程约定
- **敏感信息零入库**：密钥与 Token 仅存放在本地 `.env`，绝不进入代码、前端与版本历史；
- **时区规范统一**：API 交互遵循 ISO8601（如 `2026-10-20T10:00:00+08:00`），数据库内部统一以 UTC 存储；
- **样式采用设计令牌**：严禁写死色值与尺寸，保证系统主题可全局一键切换；
- **契约优先演进**：`contracts/**` 与数据字典具有最高约束力，任何结构变动必须先走 RFC 提案审批；
- **插件间零直接依赖**：插件之间严禁直接 `import`，所有交互只能通过事件总线、公开 API 或扩展插槽完成。

### 给 AI 协作者的工作纪律
- **契约只读**：严禁擅自修改 `contracts/**`、`manifest.json` 与公共 Schema；
- **复用已有车轮**：优先使用项目既有的抽象与工具骨架，不盲目从零发明重复机制；
- **坚守模块边界**：严禁越界修改非任务领地的配置与核心代码，跨模块需求前往 `docs/issues/` 建单；
- **拒绝虚假交付**：未完成任务必须明确标注 `partial` 并说明阻塞根因，严禁使用虚假 Mock 假充真实闭环。

## 💾 数据安全与备份

所有生活数据与配置均持久化在 **`data/`** 目录中（SQLite + WAL 模式）：

- **热备份推荐**：`sqlite3 data/alongside.db ".backup data/backups/alongside-<时间戳>.db"`（支持在线无锁备份，严禁运行中直接硬拷贝）；
- **整机迁移**：停止服务后直接复制 `data/` 整个目录即可在任意机器上无缝还原；
- `data/` 已被全局 Git 忽略，绝不会意外提交泄漏。

## 💡 参与共创

**不论你是开发者、场景设计师还是早期用户，Alongside 都有属于你的入口：**

| 你的角色 | 推荐参与路径 | 起步指引 |
|:--|:--|:--|
| **有痛点的用户** | 提交 [Issue](../../issues) | 告诉我们在生活中有哪些琐碎、重复的事情最消耗你的精力 |
| **插件/功能开发者** | 提交 Pull Request | 查阅 [插件开发 101](docs/tutorials/plugin-dev-101.md)，打造你的第一个专属插件 |
| **整合包策划师** | 提交场景模组 | 用你的场景理解，打包出适合学生备考、自由职业或科研人员的特色整合包 |
| **找茬与纠错** | 改进文档与体验 | 修正任何晦涩难懂的说明，或给现有插件补充自动化测试用例 |

> 想要深入了解整体设计思考，请阅读 [技术选型决策 (ADR 0001)](docs/adr/0001-技术栈选型.md) 与 [插件架构协议 (ADR 0002)](docs/adr/0002-插件协议.md)。
