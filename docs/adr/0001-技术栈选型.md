# ADR-0001 · 技术栈选型

- **状态**：已接受（冻结）
- **日期**：2026-09-15
- **依据**：任务书总纲 §1.1「技术栈」
- **决策者**：主人（云昔提案）
- **影响范围**：全项目（14 张任务卡）

---

> **注（2026-10-19）**：项目已定名 **Alongside**（中文「在你身边」），定位为 **AI 人生协助系统**。本文是决策当时的原始记录，其中「人生管理系统 / life-os」等表述为当时的用词，保留不改。

## 背景

要做一个**单用户的人生管理系统**，但要按"小平台"的规格来做：
可长期演进、模块可插拔、未来能持续加东西，而不是一次性写死的一堆页面。

约束条件：

1. **并发执行者不是人，是 13 个以上的子 agent**，且它们用的模型并不特别聪明。
   → 技术栈必须是**语料最厚、出错率最低**的组合，不能选冷门方案。
2. **主人是化学专业大一学生，不是后端工程师**，日常只会敲几条命令。
   → 必须有一个"唯一入口"，且**迁移成本要低**（换服务器 = 复制一个目录）。
3. **要与现有的理财工具链同语言**（AkShare / DSA 等 Python 生态）。
4. **服务器预算有限**（4C4G 级别），单用户，不该上重组件。
5. **主人明确要求"随时能换绑"**（域名 / 端口 / 服务器都不能写死）。

---

## 决策

| 层 | 选型 | 为什么是它 |
|:--|:--|:--|
| 前端 | **React 18 + TypeScript + Vite** | 生态最厚，子 agent 出错率最低；窗口管理需要精确控制 DOM 与状态 |
| 状态 | **Zustand + TanStack Query** | 窗口状态本地、服务端状态分离，避免"一个 store 打天下" |
| 样式 | **Tailwind + CSS 变量设计令牌** | 主题切换靠变量，模块不许写死颜色 |
| 拖拽 | **原生 Pointer Events + 自研吸附** | 日程表的嵌套/拉伸/跨天，通用库都表达不了 |
| 后端 | **Python 3.11 + FastAPI** | 与现有 AkShare/DSA/TSP 三件套同语言，AI 调用零摩擦 |
| ORM | **SQLModel** | 类型即模型，Pydantic v2 同源 |
| 数据库 | **SQLite（WAL 模式）** | 单用户、单文件、备份=复制文件，跑路成本最低 |
| 定时 | **APScheduler（进程内）** | 备份 / 抓取 / 日报生成够用 |
| 部署 | **Docker Compose + nginx + acme.sh** | 复用主人现有 Cloudflare DNS 签发链路 |
| 任务入口 | **跨平台 Python 脚本**（`tools/task.py`）+ Makefile 薄壳 | 见下方"实施补记" |

---

## 备选方案与否决理由

| 被否决的方案 | 否决理由 |
|:--|:--|
| **Vue** | 也行，但主力模型语料略薄；并发执行出错率更高 |
| **纯 HTML 单文件** | 撑不住 9 个可插拔模块，做不了窗口系统 |
| **Redux** | 样板代码太多，13 个 agent 会写出 13 种写法 |
| **组件库（Ant Design / MUI / shadcn 全家桶）** | 会锁死视觉；且与"一切皆插件"的设计令牌体系冲突 |
| **dnd-kit 等通用拖拽库** | 表达不了"块内嵌块 + 跨天拉伸"；日程表是本项目的心脏，不能受制于库的抽象 |
| **Node.js 后端** | 与理财侧 Python 生态割裂，AI 调用多一层摩擦 |
| **裸 SQL** | 迁移会变成地狱（表结构会长期演进） |
| **PostgreSQL** | v0.1 是单用户，杀鸡用牛刀；v0.2 若真需要再迁 |
| **Celery + Redis** | 单用户不需要消息队列，多一个组件多一处会坏的地方 |
| **裸机 systemd 部署** | 迁移更痛；容器化才能保证"开发机能跑 = 服务器能跑" |

## 后果

### 正面

- 子 agent 写代码时**有大量可参考语料**，出错率低。
- `data/` 一个目录装下全部数据，**迁移 = 复制目录**。
- 后端 Python 与主人的理财工具链同语言，`ai.tool` 扩展点可以零摩擦接进去。
- CSS 变量做令牌 → 主题切换与"插件不许写死颜色"成为可机器检查的规则。

### 负面 / 需要接受的代价

- **自研窗口系统与拖拽**意味着 T02 / T05 的工作量远大于用现成库，且没有社区兜底。
- **SQLite 单写者**：并发写入会被 WAL 串行化；对单用户足够，但要注意长事务。
- **进程内定时**意味着服务重启期间错过的任务需要补跑逻辑（T08 / T09 要注意）。
- **Tailwind 类名与设计令牌并存**，需要靠 lint / review 防止有人绕过令牌写死颜色。

### 实施补记（T01 实际执行时发现，2026-09-15）

总纲 §4 雷区 #1/#2 明确不许假设目标机器有 `make` / `grep` / `find` / `wmic`。
主人这台 Win11 **确实没有 make**。因此：

- 任务入口的真实实现放在 **`tools/task.py`**（纯 Python，跨平台）；
- 根目录 `Makefile` 退化为**薄壳**，每个 target 只是转发到 `tools/task.py`；
- 两条入口行为完全一致，文档里同时给出，主人不用记 npm / uvicorn 细节。

这不是新增技术栈，而是**把"唯一入口"这条要求落实到能真正跑起来的载体上**。
